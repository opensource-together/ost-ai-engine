# MCP Server Design Spec

**Date:** 2026-03-10
**Status:** Approved
**Scope:** v1 — public read-only access

## Overview

Add an MCP (Model Context Protocol) server to the OST Linker ecosystem, allowing developers to discover and explore open-source projects directly from Claude Desktop, IDEs, and other MCP-compatible clients.

## Architecture

```
[Claude/IDE] --> [ost-mcp (TS, npx)] --> [ost-linker API (FastAPI)] --> [PostgreSQL]
```

Two repos:
- **ost-linker** (this repo) — new FastAPI service exposing project data
- **ost-mcp** (new repo) — TypeScript MCP server distributed via npm/npx

## ost-linker Changes

### New API service

Location: `src/services/api/`

```
src/services/api/
├── __init__.py
├── main.py              # FastAPI app, uvicorn entry point
├── routes/
│   ├── __init__.py
│   ├── projects.py      # /projects/search, /projects/{id}, /projects/{id}/similar
│   ├── recommendations.py  # /recommendations/trending
│   └── references.py    # /categories, /domains, /techstacks
└── dependencies.py      # DB cursor dependency injection
```

### Endpoints

| Method | Route | Description |
|--------|-------|-------------|
| `GET` | `/projects/search?q=&category=&domain=&techstack=&limit=20` | Search projects by keyword, filterable |
| `GET` | `/projects/{id}` | Full project details with classification |
| `GET` | `/projects/{id}/similar?limit=10` | Similar projects via pgvector cosine similarity |
| `GET` | `/recommendations/trending?limit=20` | Global trending projects |
| `GET` | `/categories` | List all categories |
| `GET` | `/domains` | List all domains |
| `GET` | `/techstacks` | List all tech stacks |
| `GET` | `/health` | Health check (DB connectivity) |

Error responses follow a standard format: `{"detail": "message"}` with appropriate HTTP status codes (400, 404, 429).

No pagination in v1 — `limit` parameter caps results (max 50). Pagination can be added in v2 if dataset grows.

### DB access

Thin wrapper around `get_db_cursor()` from `src/services/python/db.py` as a FastAPI dependency (`Depends`). The existing function uses `@contextmanager` so the dependency will be a plain `yield` wrapper.

Connection pooling via `psycopg2.pool.SimpleConnectionPool` (min=1, max=5) to avoid opening/closing connections per request.

### Rate limiting

`slowapi` middleware — 60 requests/min per IP. No Redis required.

### Docker

New service in `docker-compose.yml`:

```yaml
api:
  build: .
  command: uvicorn src.services.api.main:app --host 0.0.0.0 --port 8000 --workers 1
  ports:
    - "8000:8000"
  environment:
    - DATABASE_URL
  depends_on:
    - db
```

Single worker, same Docker image as webserver. Minimal resource usage.

### OpenAPI schema

Auto-generated by FastAPI at `/openapi.json` and `/docs`. Used by ost-mcp to generate typed client.

## ost-mcp (New Repo)

### Stack

- TypeScript with `@modelcontextprotocol/sdk`
- Distributed via `npx @opensource-together/mcp`
- HTTP client auto-generated from ost-linker OpenAPI schema

### Structure

```
ost-mcp/
├── src/
│   ├── index.ts          # Entry point, MCP server setup
│   ├── tools/
│   │   ├── search.ts     # search_projects tool
│   │   ├── trending.ts   # get_trending tool
│   │   ├── project.ts    # get_project tool
│   │   ├── similar.ts    # find_similar tool
│   │   └── references.ts # list_categories, list_domains, list_techstacks
│   ├── client/
│   │   └── generated/    # Auto-generated from OpenAPI schema

├── CLAUDE.md

```

### MCP Tools (v1)

| Tool | Params | Description |
|------|--------|-------------|
| `search_projects` | `query`, `category?`, `domain?`, `techstack?`, `limit?` | Search projects |
| `get_project` | `project_id` | Full project details |
| `get_trending` | `limit?` | Trending/popular projects |
| `find_similar` | `project_id`, `limit?` | Similar projects via embeddings |
| `list_categories` | — | All categories |
| `list_domains` | — | All domains |
| `list_techstacks` | — | All tech stacks |

## Constraints

- **Host machine:** 8GB RAM Cloudflare — API must be ultra lightweight
- **Single uvicorn worker** — synchronous `def` endpoints (not `async def`) with psycopg2
- **Read-only queries** — all data pre-computed by Dagster/dbt pipeline
- **No in-memory cache** — PostgreSQL handles caching
- **Connection pool** — max 5 DB connections to limit resource usage
- **Known v1 limitation** — single sync worker serializes requests (~5 req/s max with pgvector queries). Acceptable for v1 traffic

## Scope

### v1 (current)
- Public access, no authentication
- 7 read-only tools for project discovery
- Rate limiting (60 req/min/IP)

### v2 (future)
- API key authentication via OST platform
- Personalized recommendations (`match_user_recommendation`)
- User bookmarks and preferences
- User-specific tools (`get_my_recommendations`, `get_my_bookmarks`)
